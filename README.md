# ColorsWorld 文章存档

这里保存 ColorsWorld 的历史文章。文章按发布年份归档，首页提供阅读入口。

有仓库编辑权限的成员，可以通过浏览器保存新文章并上传。**不需要改代码、重命名文件或手动编辑首页。** 也可以让能够操作浏览器和仓库的 AI 助手代办。

## 第一次使用

1. 注册并登录 [GitHub](https://github.com/)。如果管理员邀请你加入仓库，请先接受邀请。
2. 打开[本仓库](https://github.com/ColorsW0rld/ColorsW0rld.github.io)。确认已登录有编辑权限的账号。如果上传时只能提出修改请求，联系管理员确认权限。
3. 在 Chrome 中安装 **Save Page WE** 扩展。可以在 [Chrome 应用商店搜索](https://chromewebstore.google.com/search/Save%20Page%20WE)。安装后，在浏览器右上角的扩展菜单中固定它，方便点击。
4. 使用下方流程保存并上传一篇文章。能在首页打开新文章，才算完成第一次更新。

如果你是首次为整个仓库安装自动整理功能的维护者，请先完成[维护者设置](docs/maintaining-archive.md)。普通成员不需要配置自动化。

## 每次保存新文章

### 1. 在浏览器中保存

1. 用 Chrome 打开微信文章原文。若出现验证或登录提示，先完成提示，直到能读到正文。
2. 从文章顶部慢慢滚动到底部，等图片全部显示。确认没有空白图片或仍在加载的内容。
3. 点击 Save Page WE，使用保存整个页面的功能，等待保存结束。保存结果应该是**一个 `.html` 文件**。
4. 在下载文件夹中双击该文件，检查标题、发布日期、正文和图片。建议暂时断网后再打开一次，确认图片也能显示。
5. 有多篇文章时，逐篇重复。可以把下载文件放进一个临时文件夹，方便一起上传。

保留扩展生成的文件名即可，例如 `议题招募丨秋日会客厅：最微小的火种.html`。不用添加日期，不用建立年份目录，也不要将网页另存为 PDF、截图或快捷方式。

扩展的保存时间不等于文章发布日期。程序会读取文章中显示的发布日期；日期缺失时不会猜测。

### 2. 上传到仓库

1. 打开[文章收件目录 incoming](https://github.com/ColorsW0rld/ColorsW0rld.github.io/tree/main/incoming)。
2. 点击 **Add file → Upload files**（添加文件 → 上传文件）。
3. 将刚才保存的一个或多个 HTML 文件拖入上传区域。不要上传整个下载文件夹，也不要删除目录中的说明文件。
4. 等上传完成，检查文件列表。若提示同名文件已存在，先查看是否已有成员上传了同一篇文章，避免替换别人的文件。
5. 点击 **Commit changes**（提交更改），填写说明，例如“保存秋日会客厅等 3 篇文章”。
6. 选择直接提交到 `main`，确认提交。**这一步已将文件保存到远端仓库。** 如果界面只允许创建分支或提出修改请求，请让维护者协助合并；合并到 `main` 后才会自动整理。

GitHub 网页上传单个文件的上限为 **25 MiB**。超过上限时，不要压缩图片或改成 ZIP；使用下方 AI 助手方式，或由维护者通过 GitHub Desktop 上传。超过 GitHub 普通 Git 文件大小限制的文章需要维护者另行处理。

### 3. 查看整理结果

上传后，仓库会自动处理：

- 读取标题和发布日期，检查是否有正文、正文图片是否保存在文件中。
- 检查同一发布日期和标题是否已经归档。
- 将文章移入 `articles/发布年份/`，统一新文件名称。
- 为首页增加文章链接，并把整理结果再次提交到 GitHub。

打开 [Actions](https://github.com/ColorsW0rld/ColorsW0rld.github.io/actions/workflows/archive-articles.yml)，找到最新一次 **“整理上传的微信文章”**，等待运行结束，打开运行页面，查看 **Summary**（摘要）。

| 结果 | 含义与下一步 |
| --- | --- |
| 已归档，且提交归档结果成功 | 文件已进入年份目录，首页已更新，整理提交已保存到远端。 |
| 重复，未导入 | 首页中已有相同日期和标题。上传文件保留在 `incoming/`；核对已有文章后，可以删除重复上传文件并提交删除。 |
| 失败，原文件保留 | 查看摘要中的原因。原文件留在 `incoming/`，不会覆盖旧文章。 |
| 部分成功、部分失败 | 成功文章会单独归档并提交；只处理失败的文章即可。 |
| 提交归档结果失败 | 整理结果还没有推送成功，不能视为完成。远端的上传文件仍在，请联系维护者。 |

**本网站由 Render 发布，它会自动检测新提交。** 整理成功后，等待 Render 部署完成，再打开网站首页，刷新并点击新文章，检查正文与图片。GitHub 归档完成与网站发布完成是两个阶段。

确认网站能正常阅读后，可以删除电脑上的临时下载文件。需要长期保留本地副本时，也可以自行保存。

## 遇到问题

**上传后没有自动运行**：确认文件直接放在 `incoming/`，后缀为 `.html` 或 `.htm`，且已经提交到 `main`。仍未运行时，联系维护者。

**找不到日期或日期无法识别**：重新打开原文，确认页面显示完整发布日期，再保存。不要修改下载文件中的源码，也不要自行使用下载日期。

**提示图片未保存**：重新打开原文，滚动到底并等待图片加载，再用 Save Page WE 保存。先删除仓库 `incoming/` 中失败的文件并提交，然后上传重新保存的版本；如果只有这一个文件需要替换，也可以在确认文件名后上传同名文件进行替换。

**文章含视频、音频或其他嵌入内容**：单个 HTML 不保证保存这些媒体。自动整理会拒绝已识别出的嵌入媒体，请联系维护者单独备份和检查。正文图片检查也不能代替人工检查排版、背景图和特殊内容。

**误传了文件或需要删除重复文件**：打开 `incoming/` 中对应文件，在右上角菜单选择 **Delete file**，再点击 **Commit changes** 提交删除。文件很大时，GitHub 不展示正文是正常现象；删除前核对文件名。

**运行失败或网站没有更新**：将 Actions 运行页面链接发给维护者。无需重复上传整批文章。维护者可以重新运行整理；Render 的发布问题需要检查 Render 部署状态。

## 让 AI 助手代办

仓库附有中文技能文件：[保存微信文章](.agents/skills/archive-wechat-articles/SKILL.md)。它包含首次设置检查、浏览器保存、批量归档、检查结果，以及提交和推送步骤。

首次使用时：

1. 准备一个能读写本地文件、运行命令和操作 Git 的 AI 助手。希望从链接开始全程代办时，助手还需要能操作浏览器。普通网页聊天窗口通常无法直接完成这些操作。
2. 将本仓库克隆到电脑，例如在 GitHub Desktop 中选择 **File → Clone repository → URL**，填入 `https://github.com/ColorsW0rld/ColorsW0rld.github.io.git`，选择保存文件夹。登录有权限的 GitHub 账号。
3. 在助手中打开这个仓库文件夹。支持 `.agents/skills/` 的助手可以加载仓库技能；其他助手可以按下方提示直接读取技能文件。
4. 首次授权浏览器、文件夹或 GitHub 登录时，按助手提示操作。不要把密码、验证码或访问令牌写进聊天或仓库。

可以复制下面的指令，将链接换成实际文章：

> 请读取本仓库 `.agents/skills/archive-wechat-articles/SKILL.md`，按其中流程保存以下微信文章，保持现有存档结构，更新首页，并提交、推送到 GitHub。如果这是首次使用，请先检查必要设置。完成后告诉我每篇文章的结果和远端提交链接。
>
> 在这里粘贴一篇或多篇微信文章链接。

如果助手没有浏览器能力，或微信要求你手动验证，可以先按前面的流程保存 HTML，再告诉助手：

> 请读取本仓库 `.agents/skills/archive-wechat-articles/SKILL.md`，将我提供的这些本地 HTML 文件归档，更新首页，并提交、推送到 GitHub。文件位置是：……

不需要先把文件上传到 GitHub。助手可以在本地完成相同的整理后一次性提交。若助手报告没有写入权限、正文不完整或推送失败，任务还没有完成。

## 存档形式

文章保存在 `articles/年份/` 中，首页为 `index.html`。新文件采用 `ColorsWorld_YYYY-MM-DD HH_标题.html`；不能用于跨平台文件名的字符会被替换，过长标题会截短。原始 HTML 内容保持不变，旧文章路径不改动。

重复检查主要依赖首页中的发布日期和标题。历史文章可能有标题截断或不同的标点格式；补存旧文章前，请先在首页搜索标题，避免重复。

存档是纯静态文件，可继续由 Render 托管，也便于以后迁移到其他静态托管服务。
