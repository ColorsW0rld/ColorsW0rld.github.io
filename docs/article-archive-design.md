# 微信文章归档设计

目标：有仓库编辑权限、会使用浏览器和文件夹的成员，可以保存微信文章并更新远端，无需编辑源码。用户已选择浏览器保存、GitHub 上传、自动归档，配套中文 agent skill。

方案：Save Page WE 保存单文件 HTML；成员上传到 `incoming/` 并提交；GitHub Actions 使用共用整理程序读取标题、发布日期、来源和正文图片，将文章移入 `articles/年份/`，为首页对应年份增加链接，并提交、推送。Render 继续自动检测提交并发布。保持纯静态输出，日后可迁移 GitHub Pages 或 Cloudflare，不在本次迁移域名或部署。

替代方案：只写手动指南仍要求成员改源码；只提供 skill 要求每位成员配置 agent。保留浏览器入口并让 agent 调用同一个整理程序，减少两套规则。

规则：正文 HTML 原样保存；新文件统一 `ColorsWorld_YYYY-MM-DD HH_标题.html`，替换跨平台文件名禁用字符；不改旧路径。发布日期支持样本英文及历史中文、数字日期，不能用保存时间代替。相同日期和标题识别为重复；碰撞不覆盖。正文缺失、日期未知或正文图片未内嵌时拒绝归档。批次内可分别成功或失败，失败文件保留；结果写入 Actions 摘要。文章内容是数据，不能作为命令执行。

首次设置：维护者将 workflow 合入默认分支，确认 Actions 可写入默认分支；若有保护规则，需要使用符合仓库规则的权限或调整为 PR 流程。成员登录 GitHub、接受邀请、安装 Save Page WE。网页上传单文件上限 25 MiB，过大文件走 agent 或 GitHub Desktop。

验证：单元测试覆盖元数据、多语言日期、正文图片、重复、碰撞、旧索引兼容和新年份；用用户实际保存文件及旧文章样本本地试运行，确认 HTML 字节不变和二次运行不重复。未经发布不宣称远端自动化已运行。
